# CHANGELOG

本文件承接原先写在 `plugin.json` / `hooks.json` 的 `description` 里的变更史。
清单 description 每次会话都进固定前缀，只保留一行定位信息，明细放这里。

## 1.3.3（2026-10-20）

- **修复：`report.py --status` 在空端口上误报「占用者未及时响应健康检查」**。`--status` 是
  `/wb-ops:report` 判断「服务在不在跑 / 端口被谁占」的唯一依据，原来把「端口没人监听」和
  「有人占着但不应答」归成同一句话，于是对空端口也会提示「请以当前版本和配置重启旧服务」——
  助手据此会给出「去重启一个并不存在的服务」的错误建议。现在 `_probe_service()` 多返回一个
  `refused` 标记，`--status` 对空端口直接报「没有服务在监听（需要时执行 --serve 启动）」。
- **判空端口不能靠异常类型**：Windows 上连本机关闭端口可能只是**超时**而不是 `ECONNREFUSED`
  （防火墙静默丢包），按 `ConnectionRefusedError` / `errno 10061` 判会永远落到「挂死服务」分支。
  改为 `_port_free()`：自己 bind 一次，绑得上就是没人监听。

## 1.3.2（2026-10-20）

- **修复：回查被二次裁剪**。spill 落盘文件名是 `.txt`，正好命中 Read 组 `if` 白名单，于是
  「被裁后按标记去 Read 落盘文件」会和普通文本一样再被预算裁一次——只能拿到预算内的那一段，
  还会再写一份新 spill（链式放大），与「落盘可取回全文」的初衷相反。现在 `trim.py` /
  `trim.cpp` 都先判路径：落在 `<数据根>/spill/` 下一律原样透传（大小写与分隔符归一化，
  兼容 `WB_OPS_STATS_DIR` 自定义数据根）。
- **修复：并发落盘互相覆盖**。C++ 侧原先是「先 `fopen(rb)` 探测、再 `fopen(wb)` 写」，
  两个并发调用（模型一轮里发多个 Grep 很常见）可能同时判定「不存在」，后写的把先写的截断——
  标记指向的落盘内容会变成另一条工具结果，比丢文件更坏。改为 `_open(O_CREAT|_O_EXCL)` 原子独占，
  撞名换下一个序号，写一半失败删残文件。
- 一致性测试补 7 条（96 项）：落盘目录外同内容仍被裁（对照组）、反斜杠/正斜杠路径均透传、
  双实现判定一致。
- **不采纳**：`--with-read`（把所有源码文件纳入 Read 裁剪）。实测连续 8 个会话 118 次 Read
  共 148 KB、无一次超过 30 KB，按 8 KB 预算裁剪的理论节省为 0，只会给每次 Read 多付约 300 ms
  的 hook 启动成本。

## 1.3.1（2026-10-20）

- **清单瘦身（省固定前缀）**：`plugin.json` description 3859 B → 186 B，`hooks.json` 2532 B → 221 B，
  变更史迁入本文件；实测固定前缀少约 6 KB（≈1.6 K token/轮）。
- **spill 落盘（裁剪可逆）**：被省略的中段正文写入
  `~/.workbuddy/wb-ops-data/spill/<sid8>/<序号>-<tool>.txt`，省略标记追加一句取回指引
  （全量行数 + 绝对路径）；账本 `saves-*.jsonl` 新增 `spill` 字段（存相对路径，双实现同值）；
  `WB_OPS_SPILL=0` 可关。落盘的是**全文**而非中段，行号与原文一一对应，免去行号映射。
- **`gc` 一并清理落盘副本**：spill 按「7 天 / 单会话 8 MB / 总量 50 MB」清理，预算旁路文件留 2 天；
  默认只预演，`--yes` 才删。

## 1.3.0（2026-10-20）

- 省略标记给出「最长连续空洞」的取回方式（`Read offset/limit ≤180`；空洞不足 20 行不给；
  单行超长型改建议 `Grep -n`）。
- 预算随上下文水位动态收缩：<75% 用 8192、≥75% 用 6144、≥90% 用 4096，刚压缩过回到最松档；
  裁剪侧只读一份纯整数旁路文件（`<数据根>/budget/<sid8>.num`），不解析 JSON。`WB_OPS_BUDGET`
  设了非空值则完全接管。
- `.md` 单开**文档档**：门槛同结构档（800 行且超预算 + 40 KB 硬阀），中段改捞 Markdown 标题行
  （`#` 后必须跟空格/Tab，`#tag` 不算）。
- 守卫状态与预算旁路文件改「临时文件 + rename」原子写，多会话并发不再互相截断。

## 更早版本

1.2.x 及以前：`.json` 进 Read 裁剪并单列结构档（行数与字节都过线才裁 + 40 KB 硬阀）、发布链加固
（白名单打包、`--dump-exts` 三处同源校验、构建戳抓「改完忘重编译」）、Read 默认只裁数据类文件
（靠 hook 的 `if` 在 spawn 前判定）、matcher 摘掉 Bash（宿主只下发元数据，正文不在载荷里）、
失败输出按结构化信号整段透传、头尾行数按平均行长自适应。1.0.0 起冻结对外契约：环境变量、
省略标记格式、hook 事件集、数据文件格式、安装布局；破坏性改动只会在 2.0 出现。
